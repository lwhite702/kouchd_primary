## Overview

A **Guide** represents an in-app messaging component (such as an announcement banner, a welcome modal, or a check-in reminder) powered dynamically by **Knock** within the **Kouchd** application.

With Knock Guides in Kouchd:
1. **Engineering owns the UI layer**: Kouchd components match the brand colors (`#184F3A`, `#E9F3EC`, `#FFFDF8`), typography, and design tokens natively.
2. **Operations & Growth manage content**: Copy, CTAs, activation triggers, and targeting rules are configured directly in the Knock dashboard without requiring code deployments.
3. **Targeting is contextual**: Household parameters (`role: "host" | "guest"`, `stayStatus: "active" | "pending"`, `stayId`) pass automatically to guide targeting rules.

## Active Kouchd Guides

Kouchd comes pre-configured with two primary guide channels and components:

### 1. Household Notice Banner (`household-notice-banner`)

Renders a non-intrusive alert banner across the top of the active stay workspace. Perfect for quiet hours reminders, check-in countdowns, maintenance notices, and stay milestones.

- **Component**: `<KouchdGuideBanner guideKey="household-notice-banner" />`
- **Location**: Top of `<LiveStay>` in `components/authenticated-home.tsx`.
- **Supported Step Schema**:
  ```json
  {
    "title": "Scheduled Water Heater Maintenance",
    "body": "Hot water will be briefly shut off between 10am and 12pm this Thursday.",
    "primary_button": {
      "text": "View Details",
      "action": "https://kouchd.com"
    },
    "dismissible": true
  }
  ```

### 2. Welcome & Milestone Modal (`welcome-modal`)

Renders an interactive centered modal for high-priority onboarding moments, terms updates, and newly unlocked features (e.g., Kouchd Coins).

- **Component**: `<KouchdGuideModal guideKey="welcome-modal" />`
- **Location**: Mounted within `<LiveStay>` to trigger whenever eligible for the viewer.
- **Supported Step Schema**:
  ```json
  {
    "title": "Welcome to your Household!",
    "body": "Your stay agreement is active. You can now log shared grocery receipts, check chores, and review your private ledger anytime.",
    "primary_button": {
      "text": "Get Started",
      "action": "/"
    },
    "dismissible": true
  }
  ```

## Architecture & Integration

Kouchd wraps the authenticated workspace with `KnockGuidesProvider`:

```tsx
import { KnockGuidesProvider } from "@/components/knock/knock-guides-provider";
import { KouchdGuideBanner, KouchdGuideModal } from "@/components/knock/kouchd-guides";

export function SyncedWorkspace() {
  // ...
  return (
    <KnockGuidesProvider
      userProperties={{
        stayId: stay._id,
        role: membership.role,
        stayStatus: stay.status,
      }}
    >
      <LiveStay stayId={stay._id} />
    </KnockGuidesProvider>
  );
}
```

Inside `LiveStay`, custom components hook into Knock using `useGuide`:

```tsx
import { useGuide } from "@knocklabs/react";

export function KouchdGuideBanner({ guideKey }: { guideKey: string }) {
  const { guide, step, client } = useGuide({ key: guideKey });

  if (!guide || !step) return null;

  return (
    <div className="agreement-callout">
      <strong>{step.content.title}</strong>
      <span>{step.content.body}</span>
      <button onClick={() => client.markAsInteracted(guide, step)}>
        {step.content.primary_button?.text}
      </button>
      <button onClick={() => client.markAsArchived(guide, step)}>Dismiss</button>
    </div>
  );
}
```

## Environment Configuration

To connect live Knock Guides to your environment, set the following environment variables in `.env.local` or your production deployment settings:

```bash
NEXT_PUBLIC_KNOCK_PUBLIC_API_KEY=pk_test_...
NEXT_PUBLIC_KNOCK_GUIDES_CHANNEL_ID=your-guides-channel-uuid
```

> **Offline & Local Resilience**: If either variable is omitted, `KnockGuidesProvider` fails open gracefully, rendering the application cleanly without throwing errors or blocking rendering.

## Setting Up a New Guide in Knock

To create a new guide for Kouchd:

1. In the **Knock Dashboard**, navigate to **Guides** > **Create Guide**.
2. Select your channel type (`In-App Guide`).
3. Set the **Guide Key** matching your component (e.g. `household-notice-banner` or `welcome-modal`).
4. Configure your **Targeting Rules**:
   - Filter by user properties: e.g. `role == "guest"` or `stayStatus == "active"`.
5. Define the **Step Content** with `title`, `body`, and optional `primary_button` (`text`, `action`).
6. Publish the guide to staging or production.

## Frequently Asked Questions

<AccordionGroup>
  <Accordion title="How does pricing for Guides work?">
    Guides uses a monthly engaged users (MEU) pricing model based on the distinct number of users who have **seen** or **engaged** with a guide in the billing period.
  </Accordion>
  <Accordion title="Can I target specific stay roles (hosts vs. guests)?">
    Yes. Kouchd automatically provides `role`, `stayId`, and `stayStatus` in `userProperties` to `KnockGuidesProvider`. You can filter target audiences in Knock based on these attributes.
  </Accordion>
  <Accordion title="Does dismissal persist across sessions?">
    Yes. When a user clicks dismiss or the primary action button, Kouchd calls `client.markAsArchived(guide, step)` or `client.markAsInteracted(guide, step)`, which Knock remembers across reloads and devices.
  </Accordion>
  <Accordion title="What happens when Knock keys are not configured?">
    Kouchd's guide components and provider fail open safely. No network requests are made, no runtime errors are thrown, and normal household operations proceed uninterrupted.
  </Accordion>
</AccordionGroup>
