## Overview

In addition to delivering out-of-app notifications such as automated email reminders and SMS alerts for upcoming check-ins or due dates, **Kouchd** uses **Knock** to power native, in-app messaging experiences.

You can power any kind of in-app message with Knock, whether it is transactional notifications (such as household activity feeds, confirmation alerts, or toasts) or lifecycle-based messaging (such as check-in banners, agreement modals, or milestone cards).

Knock enables Kouchd to deliver these in-app messages to household members **directly in Kouchd's native product UI**, while message content, delivery rules, and triggers are configured from the Knock dashboard.

Knock provides an orchestration layer to determine:
- **Who** receives messages (e.g. hosts vs. guests, active vs. pending stays).
- **When** they receive them (e.g. upon entering a stay, completing chores, or reaching an overdue grace period).
- **Where** in Kouchd those messages are rendered (e.g. top banner on the stay dashboard, modal dialog, or notification feed).

Separating **content and presentation** allows engineering to maintain strict design system fidelity (colors `#184F3A`, `#E9F3EC`, and `#FFFDF8`, typography, and accessibility), while community and ops teams can update messaging copy and targeting dynamically without code deployments.

## Why Kouchd Builds In-App UI on Knock

- **Real-Time Ready**: Out of the box WebSocket connections ensure that as soon as an announcement is published or a guide is activated, household members see it immediately without refreshing.
- **No Data Modeling Overhead**: Handles complex messaging states automatically, including accurate badge counts, read/seen tracking, and user dismissal persistence.
- **Holistic Cross-Channel Journeys**: Knock workflows connect in-app banners with email and SMS. For example: *"Display a check-in reminder banner in the app; if unseen within 24 hours, send a reminder email or SMS based on user preferences."*
- **Composable Primitives**: Built using `@knocklabs/react` hooks (`useGuide`, `useKnockClient`) alongside custom Kouchd components, ensuring 100% adherence to Kouchd's visual styling.
- **Zero Third-Party Lag**: Guides and feeds render as native React tree nodes—never as slow iframe widgets or blocking third-party tracking scripts.

## Architecture Overview

Kouchd's authenticated workspace integrates Knock at the root level of the private stay view:

```tsx
import { KnockGuidesProvider } from "@/components/knock/knock-guides-provider";
import { KouchdGuideBanner, KouchdGuideModal } from "@/components/knock/kouchd-guides";

export function LiveStay({ stayId }: { stayId: Id<"stays"> }) {
  return (
    <KnockGuidesProvider
      userProperties={{
        stayId,
        role: bundle.membership.role,
        stayStatus: bundle.stay.status,
      }}
    >
      <div className="app-shell production-shell">
        <main>
          {/* Managed notice banner */}
          <KouchdGuideBanner guideKey="household-notice-banner" />

          {/* Managed onboarding/welcome modal */}
          <KouchdGuideModal guideKey="welcome-modal" />

          {/* Core stay view */}
          <StayDashboard bundle={bundle} />
        </main>
      </div>
    </KnockGuidesProvider>
  );
}
```

## Client SDKs Supported

While Kouchd's web client uses the **React SDK** (`@knocklabs/react`), Knock provides official client libraries across all target platforms:

- **React (Web)**: `@knocklabs/react` & `@knocklabs/client` used across Kouchd's Next.js web application.
- **React Native / Expo**: For future cross-platform household mobile clients.
- **Swift (iOS / macOS)**: For native iOS notifications and live activities.
- **Kotlin (Android)**: For Android push and in-app message rendering.

## Going to Production

When deploying Knock in-app messaging to production:

1. **API Keys**: Configure `NEXT_PUBLIC_KNOCK_PUBLIC_API_KEY` and `NEXT_PUBLIC_KNOCK_GUIDES_CHANNEL_ID` in your production environment variables (e.g. Vercel).
2. **Graceful Fail-Open**: Kouchd's `KnockGuidesProvider` is built to fail open. If keys are missing or invalid, normal household ledger operations continue without breaking or logging runtime errors.
3. **Targeting Attributes**: Pass sanitized user attributes (`role`, `stayId`, `stayStatus`) to ensure guests only receive relevant notices and hosts maintain complete administrative clarity.
